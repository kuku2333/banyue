# ADR 0001 · 用 Vue 3 + Vite 重写，内容以 Markdown 存放

- 状态：已采纳
- 日期：2026-10-21
- 取代：v1.1 单文件 `blog.html`

## 背景

v1 把博客、阅读器、听歌台、写作台全部塞进一个 279 KB 的 `blog.html`：

- 没有模块边界，改动靠「搜注释定位」，听歌一个模块就占 61 KB；
- 没有类型、没有测试、没有构建，语法错误只能在浏览器里发现；
- 发布依赖某个平台的上传流程，需要登录第三方账号。

## 决策

1. **框架：Vue 3.5 + Vite 7 + TypeScript 5.9**，SPA + vue-router（history 模式）。
   - 不选 Nuxt：这里没有 SSR/SEO 的硬需求，站点几乎全是交互型页面（阅读器、播放器），
     多一层服务端渲染只会增加部署形态和心智负担。
   - 不选 Astro：Astro 适合「以内容为主、交互为辅」的站点，而本站的重心在阅读器与播放器这类
     长驻交互上，组件级状态（播放队列、翻页、阅读位置）用 Vue 的响应式模型更直接。
2. **状态：Pinia**，只放跨页面状态（设置、播放器、阅读器）；页面内状态留在组件里。
3. **内容：Markdown + frontmatter**，放在 `src/content/posts/`，构建期用
   `import.meta.glob(..., { eager: true, query: '?raw' })` 收集。新增文章 = 新增一个 `.md` 文件。
4. **渲染：markdown-it，`html: false`**。原始 HTML 一律转义，只输出白名单标签；
   标题在渲染时注入稳定锚点，同时产出目录数据（h2/h3）。
5. **样式：手写 CSS 设计令牌 + 组件作用域样式**，不引 UI 框架。
   - 站点视觉是定制的（暗底 + 青绿 + 衬线正文），引入组件库反而要大量覆盖；
   - 全部样式集中在 `src/styles/main.css`，改配色只改 `:root` 里的变量。
6. **数据：没有后端**。v2 第一阶段的博客是纯静态；第二阶段的本地数据（书、音乐、草稿）
   走 IndexedDB，同步能力见 ADR 0002（待写）。
7. **产物：纯静态 `dist/`**。可以部署到任何静态托管（GitHub Pages / Cloudflare Pages / 对象存储），
   不绑定任何平台 SDK。

## 影响

- 加依赖、加构建步骤 → 需要 `pnpm install`；换来类型检查、单测、热更新与可拆分的模块。
- 首屏多了一个 JS bundle（约 100 KB gzip 内），换来可维护性；后续可按路由懒加载再压。
- 内容从 `.html` 里搬出来，历史文章一次性迁移完成（`web/src/content/posts/`，6 篇）。

## 备选方案与否决理由

| 方案 | 否决理由 |
| --- | --- |
| 继续维护单文件 | 61 KB 的听歌模块再叠功能会失控；无测试、无类型 |
| Nuxt 3 / SSR | 无 SEO 刚需，交互为主，部署形态复杂化 |
| Astro 群岛 | 长驻交互（播放器、翻页）跨岛共享状态别扭 |
| React + Next | 也能做，但迁移成本高、与现有 Vue 生态无关 |
